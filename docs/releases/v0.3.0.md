# pmask 0.3.0

`0.3.0` upgrades `pmask` with native `psgen` `schema: 2` profile export (zero-adapter pipeline), an unnamed `O_TMPFILE` executable carrier (`--rexec-mode=tmpfile`), instant carrier unlink on `PTRACE_EVENT_EXEC` with `SIGKILL`-safe cleanup, cross-UID `pmaskd` job isolation (`--run-as-uid[=UID[:GID]]`, `--no-dumpable`, `--allow-dumpable`), fail-closed `--profile tee` private-`/proc` validation, container and CI/CD readiness diagnostics in `pmask doctor`, `harness/score.py` parity fields in `pmask --audit --json`, and honest `--explain` output.

Release artifacts ship as static musl binaries for x86-64 and ARM64 on **GitHub Releases only** (not published to crates.io; `crates-io = false` in `Cargo.toml`) under the 0BSD license.

## Honest scope

`pmask` targets **9+/10 confidentiality and low-residue execution against a same-uid local observer, not root**. Root on the host, `CAP_SYS_PTRACE`, kernel modules, eBPF/perf tracers, hypervisors, and hardware TEE adversaries remain explicitly out of scope. See [`docs/PROFILES.md`](../PROFILES.md) for the profile ranking, `EACCES` vs cross-UID tradeoffs, container/CI guidance, and residual risks table.

## Breaking

- **`--profile-json` now emits native `psgen` `schema: 2` JSON (`"schema": 2`)**:
  - Replaces the legacy `"schema": "pmask-profile/1"` format so `pmask --profile-json` feeds directly into `psgen` without an external adapter script.
  - Emits all 18 strict top-level fields (`schema`, `source`, `identity`, `status`, `stat`, `memory`, `fds`, `auxv`, `environ`, `environ_raw_len`, `environ_all_nul`, `task`, `syscall`, `timing`, `dumpable`, `children`, `parent`, `tracer`) and scrubs sensitive env keys and secret patterns across every field (`INV-8`).
- **`--profile tee` now fails closed on refused private `/proc` mounts (exit 255)**:
  - Previously, some containers that permitted `unshare(CLONE_NEWUSER)` but refused mounting a fresh `/proc` inside the user namespace could fall back silently. `--profile tee` now probes both userns creation and the private `/proc` mount up front and exits `255` on refusal.
- **`--stealth` now uses `--rexec-mode=auto` (private path preferred) and stays silent on `hidepid=off`**:
  - `--stealth` remains a `tree`-mode preset (`--rexec`, `--watch-rename`, and hidepid-aware `--no-dumpable`) but prefers a private `0500` staged path over `/memfd:` when an executable staging directory is available, and suppresses unsolicited stderr tradeoff chatter on standard `hidepid=off` mounts.

## Highlights

- **Native `psgen` `schema: 2` export (`--profile-json`)**:
  - Both live (`--pid PID`) and static template modes emit strict `schema: 2` JSON accepted directly by `psgen` with zero unknown fields, 1-level `children`/`parent`/`tracer` capture for live PIDs, normalized `maps`/`smaps`, decoded `syscall`, and automatic scrubbing of tokens, sensitive env keys (`SECRET`, `TOKEN`, `PASSWORD`, `API_KEY`, etc.), and secret patterns (`ghp_`, `github_pat_`, `xoxb-`, `xoxp-`, `AKIA...`, PEM private keys).
- **Unnamed `O_TMPFILE` executable carrier (`--rexec-mode=tmpfile`)**:
  - Stages ELF bytes in an unnamed `O_TMPFILE` inode on an executable mount and executes via `execveat(fd, "", AT_EMPTY_PATH)`: zero directory entry is ever linked on disk (immune to `SIGKILL` at any microsecond) and zero `/memfd:` fingerprint in `/proc/<pid>/exe` and `maps`.
- **Instant carrier unlink & `SIGKILL`-safe cleanup**:
  - `--rexec-mode=path` unlinks the staged executable and removes its private `.rt-*` directory immediately at `PTRACE_EVENT_EXEC`, backed by a double-forked carrier reaper so `SIGKILL` leaves zero `.rt-*` residue in both `single` and `tree` profiles.
- **Cross-UID & `--rexec` `pmaskd` (`--run-as-uid[=UID[:GID]]`, `--no-dumpable`, `--allow-dumpable`, `--rexec`, `--no-rexec`, `--rexec-mode MODE`)**:
  - `pmaskd` now accepts `--run-as-uid=UID[:GID]` to run jobs under a dedicated service uid/gid (in addition to bare `--run-as-uid` for the connecting client's uid/gid).
  - Cross-UID jobs default to `PR_SET_DUMPABLE=1` because Linux DAC already isolates restricted `/proc` surfaces from other unprivileged uids without introducing a same-uid `EACCES` anomaly; pass `--no-dumpable` to force `PR_SET_DUMPABLE=0` or `--allow-dumpable` to keep `PR_SET_DUMPABLE=1` explicitly.
  - `pmaskd` now enables `--rexec` (`--rexec-mode=auto|path|tmpfile|memfd`, default `auto`) by default for native ELF jobs (`--no-rexec` opts out). For cross-UID `--run-as-uid` jobs, `pmaskd` verifies executable access under thread-local `setfsuid`/`setfsgid` privilege boundaries and stages an `O_TMPFILE` executable carrier owned by the target uid via `fchown`.
- **Container & CI/CD readiness diagnostics in `pmask doctor`**:
  - `pmask doctor` (text and `--json`) now reports private-`/proc` userns mount readiness (`tee` profile check), `O_TMPFILE` exec staging readiness, and `/etc/subuid` + `newuidmap` cross-UID readiness.
- **Audit & `--explain` alignment**:
  - `pmask --audit --json` adds `denied_surfaces`, `seccomp_delta`, `no_new_privs_delta`, `auxv_execfn_readable`, and `execfn_io_error` for direct parity with detection scoring harnesses.
  - `pmask --explain` accurately reports that `single` leaves `cwd` real unless `--cwd PATH` is passed (while `tee` normalizes `cwd` to `/`) and presents a clear profile ranking (`single` #1 for direct ELFs, `tree` for shells/descendants, cross-UID `pmaskd` for zero same-uid `EACCES`, `tee` for fail-closed namespaces).

## Bug fixes

- Fixed `--encrypt-memory` reporting in `--report=json` for `tree` and `tee` profiles without changing plain-run routing or forcing `--no-dumpable` when `--allow-dumpable` / `--exec-once` is used, and aligned help/docs to reflect that `--encrypt-memory` is default in `tree` and `tee` (and opt-in for the transient helper window in `single`).
- Fixed `--audit` `INV-7` formatting (`yes`/`no`/`unknown` instead of `Some(...)`/`None`), accurate `eacces_denial` and `arg_span_hidden` residual explanations under `yama.ptrace_scope` / `--observer other-uid`, and `depth > 0` ancestor `environ` allowlisting in `--profile-json --pid`.
- Added `--help-all` as a long-option alias for `--help=all`, clarified `--secret-fd` behavior in `--no-redact` mode (`RLIMIT_CORE=0`), and fixed `AT_EXECFN` dereferencing across `[stack]` page boundaries so direct reads succeed without spurious `EIO`.
- Hardened the tracee `comm` scratch page to `PROT_READ` so post-rename `/proc/<pid>/comm` stays pinned under `--watch-rename` and `--stealth`.
- Corrected documented decoy `environ` sizes across manuals and docs (`110 B` as root with `HOME=/root` or `109 B` as non-root with `HOME=/tmp`: `PATH`, `HOME`, `LANG`, `TERM`, truncated to complete entries only if the kernel window is smaller).
- Synced `bash`, `fish`, and `zsh` completions for `pmask` (`--help-all`) and `pmaskd` (`--rexec`, `--no-rexec`, `--rexec-mode`), `man/pmask.1`, `man/pmaskd.8`, `README.md`, `docs/PROFILES.md`, `tests/qa.d/62.sh`, and `tests/profiles.sh` (`P6`, `P14`-`P18`).
