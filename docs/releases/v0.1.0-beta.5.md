# pmask 0.1.0-beta.5

`0.1.0-beta.5` is the integration and stealth follow-up to beta.4. It
adds two opt-in features, a seccomp fast path for `--exec-once`, the
residual fixes from the podcrates study, and the adoption contract in
`docs/INTEGRATION.md`.

## New opt-in features

- `--hide-pid` hides the tree from same-uid `/proc` readers. It needs a
  `/proc` mount with `hidepid=invisible` or `hidepid=ptraceable`, and it
  refuses the run on a weaker mount. The kernel mechanism is
  `PR_SET_DUMPABLE=0`; `kill(0)`, `pidfd_open` and root still see the
  pid. Never the default.
- `--encrypt-memory` seals the supervisor's at-rest argv and environment
  copies with XChaCha20-Poly1305 under a per-session key in `memfd_secret`
  memory when the kernel offers it, and marks the payload's redaction
  block `MADV_DONTDUMP`. The block is anonymous on every host: a
  `memfd_secret` block would leave a `/secretmem` VMA in the payload,
  which no ordinary process has. The payload's heap and stack are not
  encrypted. A host without `memfd_secret` keeps the key in mlock'ed
  heap and the run notes it. Never the default.
- `pmask probe` has `hide-pid` and `memory encryption` rows.
  `--require=hide-pid` and `--require=encrypt-memory` work with
  `pmask doctor`.

## Performance

- `--exec-once` with `--on-exit wait` or `--on-exit kill` installs a
  seccomp filter that traps only `execve`/`execveat`, so a settled
  tracee runs with `PTRACE_CONT` between execs. The filter is installed
  once per tracee and inherited by its children. With the default
  `--on-exit detach` the tracee stays syscall-supervised, because a
  detached tracee would keep a filter with no tracer to service it.
- `measurements/bench.sh` has a `pmask-fast` variant and the results in
  `evidence/bench/`.

## Residual fixes

- `Mask`, `Prepared`, `Tracee`, `Runner` and `DaemonConfig` wipe their
  plaintext on drop. The daemon's per-job environment is no longer left
  in unlocked heap after the job.
- The daemon's peer pin fails closed when there is no pidfd and no
  readable start time.
- `userns::probe` now mounts the private `/proc` and `/tmp` in the
  throwaway child, so it proves the mounts and not only the clone.
- A successful 32-bit image under `--allow-foreign` marks the tracee;
  a later exec is refused before the new image runs.
- A vfork child that takes the post-exec path under `--exec-once` is
  counted and named, so the missing cache tag is visible.
- `--isolate` prefers a private `devpts` with `gid=0` over a bind of the
  host's, so `openpty` works when the host tty gid is not mapped.
- The test fault switches (`PMASK_FAULT_*`, `PMASK_PROBE_*`) are behind
  the `test-hooks` feature. A release build reads none of them.
- `chacha20poly1305` is 0.11, matching the podcrates workspace.
- The `std::env::args()` contract after `mask_self` is documented and
  has a control test.
- The doc defects from the study are fixed: the dangling research
  citation, the `daemon:` store example and the ChaCha/XChaCha name.

## Review fixes

- The `--exec-once` fast path no longer handles the same exec twice.  A
  seccomp stop that arrives after the syscall-entry stop is resumed, so
  a forked child's `exec` keeps its real argv (`testcases forkexec`
  prints `ONE TWO` again).
- `tests/qa.sh` fails the batch on a `FAIL` line even when the fragment
  exits 0, and reports `SKIP` when no fragment decided a case.  The
  62/63/64 fragments now exit nonzero on their own failures.
- A 32-bit image that reaches a completion stop without the entry
  refusal is counted, named and killed before it runs.  The new cases
  cover a native tracee's later 32-bit exec and the seccomp fast path.
- A completion that could not install the exec filter marks the tracee
  `fast_exec_failed`, so it stays syscall-supervised instead of running
  free.
- `--report-file` and `--report-fd` work on the plain redaction path.
  Only a `--daemon` job refuses a report.  `--daemon` with `--hide-pid`
  or `--encrypt-memory` is refused instead of running the job locally.
- The supervisor zeroes a `literal:`/`env:` secret source as soon as it
  is loaded; a second scan found the value in freed heap after the
  parser and the runner had both kept a copy.
- `--watch-rename --detach` is refused.  `--exec-once --detach` names
  that the cache is not applied.  `--stealth` prints the trade it chose
  on a `hidepid=0` host too.
- `memfd_secret(2)` is created with `O_CLOEXEC`, not `MFD_CLOEXEC`
  (0x1 is `EINVAL` on this ABI).  The capability probe, the session key
  and `SecBuf` now agree with the kernel.
- The `--exec-once` fast path also requires `PTRACE_O_EXITKILL`.  With
  `--no-exit-kill` a tracee could outlive an unexpected tracer death and
  keep the exec filter, so its next `execve` would return `ENOSYS`; the
  run now stays syscall-supervised and says why.
- `--hide-pid` with `--no-follow` or `--detach` is refused.  Both take a
  process off the completion path that re-applies `PR_SET_DUMPABLE`, and
  an exec resets the flag, so the tree-wide hide could not be held.
- `Prepared::scrub` wipes `CString` values through an owned buffer and
  clears the pointer arrays, instead of writing through a shared
  `&CString` (undefined behaviour) and leaving the arrays pointing at
  the freed allocations.
- A failed at-rest seal is counted per copy, not once per exec, so the
  "N at-rest copies could not be sealed" note matches the copies that
  stayed plaintext.  The seal and open error paths zeroize the plaintext
  they built before returning it.
- The report notes `--hide-pid` runs whose `PR_SET_DUMPABLE` injection
  failed, so `hide_pid=true` is not read as a hidden tree.
- `testhooks::bool_opt` accepts only `0` and `1`; a typo no longer reads
  as `Some(false)`.  This matches the probe parser beside it.
- `docs/DESIGN.md` said no exec-shaped seccomp filter is used.  It now
  states the fast-path guard that the code enforces.
- The project states Rust 1.87, which `ctutils 0.4.8` requires.

## Adoption

`docs/INTEGRATION.md` states the binary contract, the library contract,
the feature flags, the packaging and the limits. The short version: use
the `pmask` binary as a separate process when the caller has its own
reaper, use `SecBuf`/`SealedFd`/`Delivery` for memory hygiene, and do
not combine `--no-dumpable`/`--hide-pid` with a same-uid
`/proc/<pid>/mem` reader.

## Tests

New fragments `tests/qa.d/63.sh` (hide-pid) and `tests/qa.d/64.sh`
(encrypt-memory). The 32-bit fragment now covers the later-exec refusal.
The native gate on a fresh extraction, Debian 13, kernel 6.12.116,
uid 1000, was 1124 PASS, 0 FAIL, 30 SKIP; the QA batch is 58 fragments,
569 passed, 21 skipped.  The four-line difference from a tree that
already holds `tests/testcases32` is core.sh K4, which skips on a clean
checkout because the i686 probe is a `vm/run.sh` artifact; the micro-VM
gate builds it and covers the case.
The pinned micro-VM gate (kernel 6.12.115, QEMU, root and uid 1000) is
629 PASS, 0 FAIL, 31 SKIP, `VM-HARNESS: ALL-PASS`. The raw logs are
`evidence/round2/native-gate.log`, `evidence/round2/fresh-gate.log` and
`evidence/round2/vm-gate.log`; `evidence/round2/gates.txt` carries the
summary lines.
