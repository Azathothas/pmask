# pmask 0.1.0-beta.5

`0.1.0-beta.5` is the integration and stealth follow-up to `0.1.0-beta.4`.
This release adds `--hide-pid` and `--encrypt-memory`, introduces the `--exec-once` seccomp fast path, fixes residual issues from the podcrates study, and publishes `docs/INTEGRATION.md`.

## Breaking

- Minimum Supported Rust Version (MSRV) increases to Rust 1.87, required by `ctutils 0.4.8`.
- `pmask` refuses incompatible flag combinations with exit status 255: `--watch-rename --detach`, `--hide-pid --detach`, `--hide-pid --no-follow`, `--daemon --hide-pid`, and `--daemon --encrypt-memory`.
- `PMASK_FAULT_*` and `PMASK_PROBE_*` test hooks move behind `--features test-hooks` and are disabled in release builds.

## New opt-in features

- `--hide-pid` hides the process tree from same-uid `/proc` readers. The option requires a `/proc` mount with `hidepid=invisible` or `hidepid=ptraceable` and refuses weaker mounts. The kernel mechanism uses `PR_SET_DUMPABLE=0`. `kill(0)`, `pidfd_open`, and root still see the pid. Never enabled by default.
- `--encrypt-memory` seals at-rest supervisor `argv` and `environ` copies with XChaCha20-Poly1305. The per-session key uses `memfd_secret` memory when the kernel supports it, or `mlock`'ed heap with a visible note otherwise. The payload's redaction block stays anonymous and receives `MADV_DONTDUMP`, avoiding a `/secretmem` VMA fingerprint. Payload heap and stack memory remain unencrypted. Never enabled by default.
- `pmask probe` adds `hide-pid` and `memory encryption` rows. `pmask doctor` accepts `--require=hide-pid` and `--require=encrypt-memory`.

## Performance

- `--exec-once` with `--on-exit wait` or `--on-exit kill` installs a seccomp filter trapping only `execve` and `execveat`. Settled tracees run under `PTRACE_CONT` between execs. Children inherit the filter.
- `--exec-once` with `--on-exit detach` stays syscall-supervised so a detached tracee never keeps an unserviced seccomp filter.
- `measurements/bench.sh` adds a `pmask-fast` variant with raw logs in `evidence/bench/`.

## Residual fixes

- `Mask`, `Prepared`, `Tracee`, `Runner`, and `DaemonConfig` wipe plaintext buffers on drop. `pmaskd` no longer leaves per-job environments in unlocked heap.
- `pmaskd` peer pinning fails closed when neither `SO_PEERPIDFD` nor a readable `/proc` start time succeeds.
- `userns::probe` mounts private `/proc` and `/tmp` inside the throwaway child, verifying the mounts as well as the clone.
- A 32-bit image allowed via `--allow-foreign` marks the tracee so later execs are refused before running.
- `--exec-once` counts and reports `vfork` children that take the post-exec path without the cache tag.
- `--isolate` prefers a private `devpts` mount with `gid=0` over binding host `devpts`, fixing `openpty` when the host tty gid is unmapped.
- Test switches (`PMASK_FAULT_*`, `PMASK_PROBE_*`) live behind `--features test-hooks`. Release builds ignore all of them.
- `chacha20poly1305` updates to `0.11`.
- `docs/INTEGRATION.md` documents the `std::env::args()` contract after `mask_self`, backed by a control test.
- Fixed study documentation defects: dangling research citation, invalid `daemon:` store example, and ChaCha vs XChaCha naming.

## Review fixes

- Fixed double handling of a single exec on the `--exec-once` fast path. A seccomp stop arriving after a syscall-entry stop resumes cleanly, preserving real `argv` in forked children (`testcases forkexec` prints `ONE TWO`).
- `tests/qa.sh` now fails on any `FAIL` line even when the fragment exits 0, and reports `SKIP` when no case is decided. Fragments 62, 63, and 64 exit nonzero on failure.
- A 32-bit image reaching completion without entry refusal is counted, named, and killed before execution. New tests cover native later 32-bit execs and the seccomp fast path.
- Failed exec-filter installation marks the tracee `fast_exec_failed`, keeping it syscall-supervised instead of running free.
- `--report-file` and `--report-fd` now work on the plain redaction path. Only `--daemon` jobs refuse reports. `--daemon` refuses `--hide-pid` and `--encrypt-memory` instead of falling back to local execution.
- The supervisor zeroes `literal:` and `env:` secret copies immediately after loading.
- `--watch-rename --detach` is refused. `--exec-once --detach` notes that the cache is inactive. `--stealth` prints its trade on `hidepid=0` hosts too.
- `memfd_secret(2)` now passes `O_CLOEXEC` instead of `MFD_CLOEXEC` (fixing `EINVAL` in the probe, session key, and `SecBuf`).
- The `--exec-once` fast path requires `PTRACE_O_EXITKILL`. With `--no-exit-kill`, the tracee stays syscall-supervised and explains why.
- `--hide-pid` refuses `--no-follow` and `--detach` because exec resets `PR_SET_DUMPABLE` and breaks tree-wide hiding.
- `Prepared::scrub` wipes `CString` values through an owned buffer and clears pointer arrays cleanly.
- Failed at-rest seals count per copy rather than once per exec. Seal and open error paths zeroize plaintext before returning.
- JSON reports record failed `PR_SET_DUMPABLE` injections under `--hide-pid`.
- `testhooks::bool_opt` accepts only `0` and `1`, matching the probe parser.
- Updated `docs/DESIGN.md` to document the `--exec-once` fast-path guard.
- Set `rust-version = "1.87"` in `Cargo.toml`.

## Adoption

`docs/INTEGRATION.md` defines the binary contract, library contract, feature flags, packaging, and limits.
Use the `pmask` binary as a separate process when your caller owns its own child reaper.
Use `SecBuf`, `SealedFd`, and `Delivery` for in-process memory hygiene.
Do not combine `--no-dumpable` or `--hide-pid` with a same-uid `/proc/<pid>/mem` reader.
