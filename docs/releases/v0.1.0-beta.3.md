# pmask 0.1.0-beta.3

The third beta. It corrects the claims the 0.1.0-beta.2 documentation made
that the code did not support, and fixes the two behaviours those claims
exposed. No redaction mechanism changed: the exec-entry swap, the window
relocation and the post-exec paths are the same code.

## Breaking

- `--report-file` narrows the file to 0600 whether it created it or not.
  0.1.0-beta.2 applied the mode only on creation, so an existing 0644
  report file kept its mode and the run's report was readable by every
  local account. A deployment that relied on a group-readable report file
  now has to copy it after the run.
- `--exec-once` under `--redact --isolate` prints one line naming the
  reason it is unavailable. The option was already disabled there; the
  line is new, so a script that asserts on empty stderr will see it.

## Fixes

- `--report-file` calls `fchmod(0600)` after the open, so the mode holds
  for an existing file. `tests/qa.d/9.sh` creates a 0644 file, runs, and
  asserts the mode is 600 afterwards.
- `--exec-once` names the namespace reason. `Mask::to_config` cleared the
  per-exec cache whenever a namespace set was requested, but the warning
  block only knew about `--unshare` and `--run-as`, so `--redact
  --isolate` dropped the cache silently. That is the invariant-13
  failure: a degradation the operator cannot see. `tests/qa.d/61.sh`
  covers the namespace reason, the `--unshare` reason, and a control run
  that keeps the cache and prints neither.

## Documentation

Every correction below is a claim the code or a test contradicted. The
mechanism did not change; the sentence did.

- `README.md` installs from an explicit tag. Every pmask release so far
  carries a suffix, GitHub publishes a suffixed tag as a prerelease, and
  `releases/latest` skips prereleases, so the documented `curl` returned
  404. The example now names the tag.
- `README.md` and `docs/THREAT-MODEL.md` say what `--detach` does to the
  tracer thread: it zeroes each tracee's `TracerPid`, and the
  supervisor's thread lives for the session. The old text said `--detach`
  had no tracer, which the code contradicts.
- `docs/THREAT-MODEL.md` states the `mem_canary_readable` column as it is
  measured: 1 in the control, redacted and detached rows, and `SKIP` in
  `redacted-nodumpable`, where `--no-dumpable` refuses the open. The old
  text said "yes in every row".
- `README.md` and `docs/THREAT-MODEL.md` scope the `AT_EXECFN` rewrite to
  the runs where the window relocation happens; `--no-exact` and a
  refused `PR_SET_MM_MAP` leave the auxv alone, which `tests/qa.d/43.sh`
  asserts.
- `docs/THREAT-MODEL.md` adds the script exception to the `--no-exact`
  span: a script payload keeps the original extent on its post-exec path.
- `README.md` describes `--secret-fd-name` as 1 to 200 bytes with no
  slash, no C0 control byte and no DEL, which is what
  `validate_memfd_name` enforces. The old text said "printable bytes".
- `README.md` says `map_files` resolves to a `/memfd:` target, which is
  what `tests/compare.sh` asserts, and names the full
  `/memfd:<label> (deleted)` text as what `readlink` shows.
- `README.md` names both unit paths: `pmask-run@.service` uses
  `/usr/bin/pmask` and `pmaskd@.service` uses `/usr/bin/pmaskd`.
- `README.md` and the 0.1.0-beta.2 notes say the micro-VM gate runs nine
  staged suites, not "the full suite"; `vm/common.sh` names the seven it
  does not stage.
- The 0.1.0-beta.2 notes scope `--memfd-name` to the memfd carriers and
  name the `--exec-once` tag as that name sanitised and cut to 64 bytes.
- `src/rexec.rs` loses a doc comment that contradicted itself in two
  consecutive sentences about the temporary-file carrier.
- `evidence/bteam4/51/README.md` says which of the two logs is the
  pre-fix run, so the `VERDICT: FAIL=2` line is not read as the state of
  the fragment at this tag.

## Tests

- `tests/qa.d/61.sh` is new: the `--exec-once` namespace warning, the
  `--unshare` warning, and a control that keeps the cache.
- `tests/qa.d/9.sh` gains the existing-file mode row.

## Binaries

| file | system |
| --- | --- |
| `pmask-x86_64-unknown-linux-musl`, `pmaskd-x86_64-unknown-linux-musl` | Linux x86-64 |
| `pmask-aarch64-unknown-linux-musl`, `pmaskd-aarch64-unknown-linux-musl` | Linux ARM64 |

Each binary is static (musl). `pmask.1` and `pmaskd.8` are the manual
pages. `pmask-0.1.0-beta.3-<target>.tar.gz` adds the completions and the
systemd units.

## Install

```sh
V=v0.1.0-beta.3
curl -fLO "https://github.com/Azathothas/pmask/releases/download/$V/pmask-x86_64-unknown-linux-musl"
chmod +x pmask-x86_64-unknown-linux-musl
./pmask-x86_64-unknown-linux-musl --version
```

## Check a download

```sh
sha256sum -c --ignore-missing SHA256SUMS
gh attestation verify pmask-x86_64-unknown-linux-musl --repo Azathothas/pmask
```

## Limits

The limit table in `README.md` is the contract. Root on the host sees
that a pid exists and can read its memory; `cmdline` and `comm` are
readable by every local account; `environ`, `exe`, `maps` and `fd/*`
are readable by the same uid unless `--no-dumpable` is set. The launch
window, the audit record and the packaged `.comment` remain.

## What to report

Open an issue with `pmask --version`, `pmask probe`, the kernel and the
command. Report a vulnerability through `SECURITY.md`, not a public
issue.
