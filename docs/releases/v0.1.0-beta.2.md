# pmask 0.1.0-beta.2

The second beta. It lands the Team Red QA sweep over the 57 open issues
and the dependabot actions bump, plus the review fixes that followed.

The mechanism is unchanged: redaction still happens at the true
`execve` entry stop, the payload keeps its real `argv` and `envp`, and a
32-bit image is still refused loudly rather than half-redacted.

## Breaking

- `--report` accepts only `json`. `text` and `plain` were accepted and
  silently produced the default summary; they are now a usage error that
  names the default.
- `--report-fd` must be above 2. 0, 1 and 2 are refused because the
  report descriptor is close-on-exec, so the payload would start with
  that stream closed.
- `--report-file` refuses a symlink and narrows the file to 0600, whether
  it created it or not. A planted symlink can no longer truncate its
  target, and an existing 0644 report file no longer hands the run's
  report to every local account.
- `--comm` is refused when it is longer than 15 bytes or contains NUL,
  LF or CR, in every mode. Redaction mode already refused the length;
  plain and isolate now agree.
- `--env` refuses a name that is empty or contains `=`, NUL, a space or
  a byte outside printable ASCII, in every mode. `--env-file` already
  used this grammar; one rule now covers both surfaces.
- `--secret` and `pmask get`/`store get` refuse a name containing LF or
  CR. The name is pasted into the agent's line protocol.
- `--socket-mode` refuses 0 and values above `0777`. A 000 socket is
  bound and then unreachable with no warning.
- `pmask get` returns 255 for a transport, protocol, locked-store or
  policy error and 1 only for a name the agent does not hold.
  `store get` and `get` return 255 when the write fails.
- `--isolate` is decided before the ptrace check: a host that refuses
  ptrace but grants user namespaces now gets the namespaces instead of
  plain mode. `--redact --isolate` composes; `--no-redact --isolate`
  isolates; `--isolate=none` creates nothing.
- `--exec-once` is disabled under a namespace set, where the cached path
  is not visible to the tracee, and the run names that reason. The
  `--unshare` and `--run-as` reasons print as before.
- `pmaskd`'s PING body is reduced for a peer that is neither the
  daemon's own uid nor root: protocol, detail, label, uid and
  run_as_uid only. The full body keeps the policy fields.
- `--audit` is refused where the selected mode does not redact, rather
  than printing nothing.

## Fixes

- `--unshare` and `--redact --isolate` no longer silently skip
  redaction: the handshake is `PTRACE_INTERRUPT` on the seized master,
  not a self-directed `SIGSTOP` a pid-namespace init cannot receive.
- `--watch-rename` with `--no-dumpable` redirects the rename to the
  label already mapped in the tracee and refuses an unfixable rename
  with `EFAULT` instead of letting the payload choose its own `comm`.
- The supervisor's secret memfd is `MFD_CLOEXEC`; a failed 32-bit exec
  settles back to syscall supervision so the next exec is redacted.
- The private `/dev` carries the host's `/dev/pts` and `/dev/ptmx` and a
  private `/dev/shm`, and names each member it could not provide.
- `--hugetlb --image -` and `--image-from-fd` fall back to an ordinary
  memfd; `--args-from-fd` duplicates the caller's descriptor;
  `--memfd-name` and `--secret-fd-name` use the same name on every memfd
  carrier, and the `--exec-once` temporary-file tag is that name
  sanitised and cut to 64 bytes.
- `--env-file` has one grammar in `pmask` and `pmaskd`; the daemon's job
  deadline is bounded; SIGTERM wakes a daemon whose client is silent
  with `--io-timeout 0`; `doctor --json` escapes every string and
  refuses an empty `--require`.
- `-q` reaches the isolation report; `--env =VALUE` is refused by the
  parser in every mode; an unknown `--secret` scheme is a warning, not a
  silent literal.

## Tests and documentation

- 54 per-issue fragments under `tests/qa.d/`, dispatched by
  `tests/qa.sh`; the dispatcher reports `passed=` and `skipped=` so a
  batch of skips cannot read as coverage.
- `isolation.sh`, `compare.sh` and `conformance.sh` run in CI, and the
  micro-VM gate runs nine staged suites as root and uid 1000; the seven
  whose cases need a compiler, a session manager or a real store are
  named as skipped there.
- `scripts/check-completions.sh` fails the build when the parser grows
  an option the tables do not offer.
- `README`, `SECURITY`, the threat model, the man pages and the source
  comments state what the code now does: the reduced PING body, the
  supervisor's non-dumpable scope, the `literal:` audit exposure, the
  store owner, the exit-status contract, the mode table and the
  measured launch window.
- `docs/ISSUE-CLOSURE.md` records, per issue, the fix commit, the test
  that would fail if the behaviour changed, and the evidence directory.

## Binaries

| file | system |
| --- | --- |
| `pmask-x86_64-unknown-linux-musl`, `pmaskd-x86_64-unknown-linux-musl` | Linux x86-64 |
| `pmask-aarch64-unknown-linux-musl`, `pmaskd-aarch64-unknown-linux-musl` | Linux ARM64 |

Each binary is static (musl). `pmask.1` and `pmaskd.8` are the manual
pages. `pmask-0.1.0-beta.2-<target>.tar.gz` adds the completions and the
systemd units.

## Install

```sh
curl -fLO https://github.com/Azathothas/pmask/releases/download/v0.1.0-beta.2/pmask-x86_64-unknown-linux-musl
chmod +x pmask-x86_64-unknown-linux-musl
./pmask-x86_64-unknown-linux-musl --version
```

## Check a download

```sh
sha256sum -c --ignore-missing SHA256SUMS
gh attestation verify pmask-x86_64-unknown-linux-musl --repo Azathothas/pmask
```

## What to test

- `pmask --label ci-runner ./deploy.sh --token "$TOKEN"` on a host where
  `kernel.yama.ptrace_scope` is 0 or 1.
- `pmask probe` and `pmask doctor --require redact,exact` on the kernels
  you care about.
- `pmaskd` with a socket in a private directory, and `pmask --daemon`.
- `--secret`, `--isolate`, `--no-dumpable` and `--rexec` on the
  filesystems you use.
- A 32-bit image, a script, a `vfork` child and a re-exec, which take
  the documented post-exec paths.

## Limits

The limit table in `README.md` is the contract. Root on the host sees
that a pid exists and can read its memory; `cmdline` and `comm` are
readable by every local account; `environ`, `exe`, `maps` and `fd/*`
are readable by the same uid unless `--no-dumpable` is set. The launch
window, the audit record and the packaged `.comment` remain.

## What to report

Open an issue with `pmask --version`, `pmask probe`, the kernel and the
command. Report a vulnerability through `SECURITY.md`, not a public
issue.
