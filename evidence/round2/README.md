can still see of a pmask-supervised tree, on this host, with the binaries
present at the time of the run. Every number below comes from a command whose
raw output is in the referenced log next to this file. No source file was
modified by this audit; the source modifications that `git status` already
reports predate it (the red team's fixes), and `evidence/round2/` is the only
untracked path this audit added.

Two host facts matter for reading the results:

1. **hidepid=0.** `--hide-pid` cannot be measured on the system `/proc`. Case 7
   therefore mounts a private `/proc` inside `unshare -m -p` and measures
   there; that is the host policy the option needs, not a different kernel.
2. **A seccomp filter is inherited from the container runtime.** A plain
   control process shows `Seccomp_filters: 1`, not `0`. The *delta* introduced
   by pmask is still visible (1 → 2), but the absolute baseline claimed in the
   README does not hold on this host. See "Claims contradicted".

## Method and tools

- `tools/procdump.py PID TAG` — reads one pid's `/proc` surface as the calling
  uid. Prints `open=`/read results for `environ`, `maps`, `auxv`, `exe`, `fd`,
  `mem`; cmdline hex and text; comm; stat fields 48–51; `AT_EXECFN` from
  `/proc/pid/auxv` and the string it points at through `/proc/pid/mem`; status
  `TracerPid`/`Seccomp_filters`/`NoNewPrivs`; the full maps list; the fd list.
- `tools/scanmem.c` → `tools/scanmem` — root/owner scanner over the readable
  mappings of one pid for literal byte strings. Reads 1 MiB chunks plus a
  needle-length overlap, so a needle on a chunk boundary is not missed.
- `tools/uidprobe.py PID TAG` — the exact errno for `stat`, `open` of each
  sensitive file, `readlink exe`, `listdir fd`, `readdir /proc`, `kill(0)`.
- `tools/sample_status.py LABEL SECONDS` — polls `/proc` every ~0.5 ms, so a
  payload that lives a few milliseconds (`forkexec / /bin/echo`) can still be
  caught with its status line.
- `tools/caseN.sh` — the runner for case N. It contains the exact commands,
  the control runs and the cleanup. `tools/lib.sh` holds `start_bg`,
  `find_pids`, `supervisor_pid`, `payload_pid`, `stop_pgid`.
- Cleanup: every runner kills its session group and asserts that no labeled
  process remains. Final check: `ps -eo pid,ppid,user,comm | grep -E
  'pmask|testcases|r2-'` → no matching processes, including as root.

Controls: cases 1, 2, 3, 6 and 7 have a no-pmask control run twice. Case 8's
control is a plain process holding the same two strings, scanned twice; that
also validates the scanner. Case 4 and 5 have two masked runs each.

### Handling note (credential exposure, corrected)

The first revision of `r2-def.log` printed 400 bytes of the control process's
inherited environment. That environment contains live-looking credentials
(`GH_TOKEN`, `ERRAND_PROVIDER_PG_*`). I stopped, changed `procdump.py` to print
only `environ.len` and variable **names**, and regenerated the log. A grep for
`ghp_[A-Za-z0-9]{10,}|errand-session-[0-9a-f]{10,}` over `evidence/round2/`
now returns no files. The values were written to disk once and shown in the
session transcript, so they must be treated as compromised; deleting the line
does not undo that. No evidence file contains them now.

## Claims in the tree's docs that these measurements contradict

1. **"five EACCES opens" is six paths (fixed in the tree).** README line 127 said
   "`environ`, `maps`, `auxv`, `exe` and `fd`, and `/proc/<pid>/mem` is
   refused ... five `EACCES` opens"; README line 56 says the same six items
   "and the five refusals"; the `--stealth` trade line prints "Those five
   EACCES refusals". Measured: **six** distinct paths return `EACCES` for a
   same-uid reader — `environ`, `maps`, `auxv`, `exe` (both `readlink` and
   `open`), `fd`, `mem`. `r2-nodump.log`, `r2-stealth.log`.

2. **The `--stealth` row claimed a same-uid observer sees a `/memfd:` `exe` (fixed in the tree).**
   README line 57: "the same, with `--stealth` | the label, a `/memfd:` `exe`,
   and the `--no-dumpable` refusals on a `hidepid=0` host". Measured: the
   same-uid `readlink`/`open` of `exe` returns `EACCES`; the `/memfd:r2-stealth
   (deleted)` target is visible only to root. The row describes a reader who
   cannot simultaneously receive the refusals. `r2-stealth.log`.

3. **"an ordinary process carries `0` and `0`" does not hold on this host (fixed in the tree).**
   README line 599 (the seccomp fingerprint row) says an ordinary process
   carries `Seccomp_filters: 0` and `NoNewPrivs: 0`. The no-pmask control on
   this host carries `Seccomp_filters: 1` and `NoNewPrivs: 0`, because the
   container runtime installs a filter. The masked delta is real (1 → 2), but
   the absolute baseline is host-dependent; a detector must compare against
   the host's own baseline, not the documented zero. `r2-def.log`,
   `r2-rename.log`.

4. **The supervisor's `auxv` named the tool (fixed in the tree).** The
   first round measured `auxv.execfn_string='/workspace/pmask-work/target/release/pmask'` on the dumpable supervisor.  The second round rewrites the
   supervisor's own `AT_EXECFN` to the label when `PR_SET_MM_MAP` is
   permitted, and re-measures `auxv.execfn_string='r2-def'`.  On a host that
   refuses the relocation, the field still names the pmask binary and the
   README row says so. `r2-def.log`.

5. **The memfd-name fingerprint row omits the `--exec-once` second-exec
   carrier.** README line 595 lists `/proc/<pid>/exe -> /memfd:<label>
   (deleted)` for the image family. Measured under
   `--exec-once --on-exit wait`: the second exec's `exe` is
   `/dev/shm/.pmask-rexec-r2-once-241909-0b9a92da-0`, and the supervisor's fd
   211 is the same `.pmask-rexec-` name. This is a different, more explicit
   tool name than the row documents. `r2-once.log`.

Claims checked and **not** contradicted (selected): default `cmdline`/`comm`/
`environ`/`AT_EXECFN` redacted; `--no-dumpable` refuses the six paths;
`--stealth` applies `--no-dumpable` on hidepid=0 and prints its trade;
`--encrypt-memory` puts `/secretmem` in the supervisor and not the payload,
`block_secretmem=false`, `block_anonymous=1`; the secret literal is absent
from supervisor memory; `--hide-pid` gives `ENOENT` on `invisible` and `EPERM`
on `ptraceable` while `kill(0)` and root still see the pid; the report's
`"mode"` is `"redact"` on the default path.

## Scope, limits and what was not measured

- This is one host (LXC, kernel 6.12.116, Debian 13, uid 1000, hidepid=0).
  Case 7's hidepid results come from a private `/proc` in a new mount+pid
  namespace, not from the system mount.
- `--stealth` was measured on hidepid=0 only; the documented hidepid=invisible
  branch of `--stealth` was not exercised.
- Case 5's `maps` content and `mem` content, case 4's payload `AT_EXECFN`, and
  case 8's payload `AT_EXECFN` value were not captured; they are marked n/m in
  the table. Their `open` results were captured.
- The `--no-dumpable` case measures the six refusals; it does not attempt a
  `ptrace` attach or a core dump.
- No full test suite was run, per the task. No source file was changed.
